# 03 · 出价瀑布 · 三态峰值 · 末段窒息

> 用户直觉：「出价成功不只是一条弹幕飘过，可以像瀑布一样落下来」+「领先时『🎉领先！』、被超越时『⚡被超越！』的情绪反馈不够震撼」。
> 现状证据：每笔出价 = 一条 6.2s 飘过的玻璃药丸（`system-barrage`，`styles.css:358-403`）+ 一个 1.7s 居中淡入淡出 toast（`atmosphere-cue`，`styles.css:666-727`，标题 22px）。**快速连拍时是「一串弹窗弹出又消失」，不是「越来越燃的场」。** 落槌 = 小 toast + 74px「成交」角标（`styles.css:625-645`）→ 立即转支付。

本篇是氛围栈 L3（事件脉冲）+ L4（峰值仪式）+ L2（末段升温）+ L6（触觉音频）的合体，构成全场最强记忆点。

---

## A. 出价瀑布（Bid Waterfall）— L3

### A.1 设计
把「单条飘屏」换成**级联瀑布**：每一笔**引擎接受**的出价，从竞速榜/价格区**落下一枚出价芯片**（金额 + 脱敏名 + ↑），沿一条右侧瀑布道下坠、轻微堆叠后淡出。**落片密度 = 真实出价速率（IntensityModel，`01`§2）**：

```
I=1 温：     I=2 热：        I=3 沸（数百人狂点）：
  ▫              ▫ ▫            ▫▫ ▫ ▫▫
                ▫              ▫ ▫▫▫ ▫
  ▫ ¥420         ▫ ¥440        ▫▫▫ ¥480 ▫▫
                ▫ ▫            ▫ ▫▫ ▫ ▫▫   ← 像倾盆，而不是一条线
```

- **每片 = 一个真实事件**：`bid_accepted`（带 `engine_seq` + 金额 + 脱敏出价人）。**没有装饰性假片**。
- I=3 时密度高到形成「瀑布感」——这正是把热度计的数字（「近30s 12 次」）翻译成**可感的能量倾泻**，兑现宣讲版「数百人狂点」。
- 自我出价的片**更亮 + 金边 + 轻微放大**，让「我刚出的那一口」在瀑布里被一眼认出。

### A.2 你比别人强在哪
- 微拍堂靠主播口播「又有人扣1了」；抖音飘屏是**打赏**驱动（与拍卖无关）；本方案的瀑布**每片都是一次真实有效出价**，密度即真实竞争烈度——**热闹且诚实**。
- 对比现状单飘屏：从「通知流」变「能量场」，是「平淡 → 震撼」的关键一跳。

### A.3 技术（canvas，性能预算严格）
- **canvas 单层 + requestAnimationFrame + delta-time**：瀑布用一块 canvas 画所有芯片（DOM 在 I=3 会有上百节点合成压力；canvas 一次重绘胜过上百合成层——见 `references` 动画工程：弹幕 >~100 并发须 canvas）。
- **粒子上限 + 背压**：同屏芯片上限（如 24），超出丢弃**最旧**（保留最新出价的视觉优先级）；隐藏标签页自动暂停（rAF 特性）。
- **只动 transform/opacity**；`prefers-reduced-motion` → 关瀑布，回落为竞速榜内「+1 次」计数跳动（信息不丢）。
- 复用既有 `system-barrage` 作为**主播/AI 系统消息**通道（横向飘屏），**与瀑布（纵向、出价事件）分工**：横向=话语，纵向=出价能量。

## B. 三态强反馈（领先 / 被超越 / 落槌）— L3→L4

把 1.7s 小 toast 升级为**多感官时刻**。三态共用现有 `atmosphere.ts` cue 管线（去重/优先级/单调 id 已就绪 `atmosphere.ts:33-60`），升级的是**呈现幅度**：

| 态 | 现状 | 3.0 升级 | 真实信号 |
|---|---|---|---|
| 🎉 **领先** | 顶部金绿 toast 1.7s + 细金描边环 | 价格**odometer 滚字上扬**(金) + 全屏自上而下**金色扫光**(一次,≤700ms) + 竞速榜「我」升顶高亮 + 轻震 + 上扬金币音 | `bid_accepted` 且 `my_rank=1` |
| ⚡ **被超越** | 红边 980ms 闪 + toast | 屏幕边缘**红光一记「砸」**(短促) + 居中「被反超 **¥50**」(真实差额) + **「立即反超 →」**行动召唤 + 双段震动 + 下沉音 | `outbid`/`me.rank` 1→>1（事件驱动,§02-7） |
| 🔨 **落槌** | 1.7s toast + 74px 角标 → 转支付 | 见 §D 落槌高潮 | `sold`（引擎权威终态） |

**关键工艺**：
- **被超越用「真实差额」而非泛化文案**——这是**真·near-miss**（Clark 2009 神经科学：差一点会激活「赢」的脑区，驱动再出价），但**用的是引擎给的真实 `gap`，不是编造**。这正是「真实信号 hype」与「赌博式假近失」的分界线。
- **odometer 价格滚字**：纯 CSS translateY 数字条（0KB，合成层，见 `references` 动画工程 §4），价格上跳时滚动，比现有 `price-tick`（仅变色微移 `styles.css:1474`）更有「钱在涨」的体感。
- 领先扫光/被超越红砸都是**一次性 ≤700ms**，不循环、不糊；快速连拍由 cue 优先级（sold>extended>outbid>leading）+ 去重保证不打架。

## C. 末段窒息系统（Final-seconds Suffocation）— L2+L6

> 直击核心挑战「价格每秒都在跳动，气氛紧张到窒息」。现状末段仅 `hammer-beat-layer` 文字节拍（`styles.css:1090`），**无变色/脉冲/心跳/震动的升温曲线**——从正确性看完美，从情绪看与「高潮」相反。

### C.1 升温曲线（随真实剩余秒数连续加强）
| 剩余（服务端校时） | 视觉 | 音 | 触觉 | 文案 |
|---|---|---|---|---|
| ≤10s | 舞台边缘渐入警示红晕（已有 `countdown-phase` 钩子 `styles.css:647`）+ 价格/倒计时脉冲 | 心跳音床淡入(可关) | — | — |
| ≤5s | 红晕加深 + 脉冲加速 | **心跳 tempo 渐快** | 轻震脉冲 | 「going once / 第一次」 |
| ≤3s | 屏幕呼吸式收束 | 心跳最快 + 滴答 | 震动渐强 | 「二次 / 三次」节拍 |
| soft-close 触发 | 倒计时**拉伸动画** + 竞速榜抖动 | 提示音 | — | **「+10s 延时！还有人在拼」**（可视化延时） |

### C.2 soft-close 可视化（对标全球标杆）
- TikTok Shop Extended Auction **明确把延时时长显示在 UI**；Whatnot Standard 每次新出价加几秒；苏富比 +2min 至安静。本项目**已有自动延时引擎**，但末段延时事件**没有被「演」出来**。
- 3.0：`extended` 事件 → 倒计时拉伸 + 「延时 +10s」浮层 + AI 气氛官一句「最后关头有人反超，延时！」（`04`）。把「防狙击」从隐形规则变成**全场最爽的反转时刻**。
- 同时上屏 Whatnot「Sudden Death 💀」式的**模式标识**（若该件为不延时硬结束），让买家知道「这件没有延时，手要快」——规则透明即信任。

### C.3 门控（铁律）
末段升温**仅在** `ACTIVE && !recovering && !stale && !disconnected` 时触发；断连/恢复期**绝不升温**（不制造「假窒息」）。reduced-motion → 保留文字节拍 + 音/震动，去视觉脉冲。

## D. 落槌高潮 + 战绩卡 + 惜败收尾 — L4

> 现状：赢得稀世翡翠的高光被处理成「结账」。`ResultSheet` 已有 `result-confetti-fall`/`result-cinematic-glow` keyframe（`styles.css:2348-2370`），但落槌→立即转支付，缺编排。

### D.1 赢家高潮序列（先于支付，约 2.5s）
1. **落锤音**（真实音效，非单振荡器 beep）+ 全屏一记定格。
2. **礼花瀑布**（canvas-confetti，`useWorker` 跑 OffscreenCanvas/Worker，**不占主线程**；自定义金币/拍品形状；`disableForReducedMotion`）——与 §A 出价瀑布呼应：**出价时片片落下，落槌时礼花倾泻**。
3. **赢家聚光** + 「中拍！」+ odometer 定格成交价。
4. **可分享战绩卡**：拍品图 + 成交价 + 击败人数(真实) + 价格曲线(真实) + 「全程 N 次出价反超 M 次」——病毒传播 + 记忆锚点（对标 Fanatics「feel the reveal」、TikTok Surprise Set 揭晓、WSC 自动高光）。**战绩卡先出现，再进支付**。

### D.2 惜败温柔收尾（差异化的「人味」）
- 输家不是冷冰冰「未中拍」，而是「**差一口 ¥50 · 你已尽力**」+ 「下一件 30s 后开拍，提醒我」钩子。
- 既是留存（把惜败的损失厌恶导向下一场），也是**反暗黑**：不羞辱、不诱导追价，诚实收尾。

### D.3 你比别人强在哪
- Pop Mart 拆盒/Whatnot reveal 的高潮是**赌博揭晓**；本方案的高潮是**「你真的赢了一件真东西、以一个可对账的真实价格」**——同样的多巴胺，但**经得起『这数字哪来的』追问**（战绩卡每个数字可回链 `engine_seq`/订单）。

## E. 技术规格汇总（工业级落地）

### E.1 动画栈决策（来自 `references` 动画工程；原则：能 0KB 就 0KB，重的懒加载）
| 用途 | 选型 | 体积 | 关键点 |
|---|---|---|---|
| 竞速榜名次重排 | **保留手写 WAAPI FLIP** | 0KB | 已有、合成层、off-main-thread |
| 价格滚字 | **CSS translateY 数字条**(手写) | 0KB | 合成层；reduced-motion 即时 |
| 出价瀑布 | **canvas + rAF**(手写) | ~0KB | 单层重绘、粒子上限、隐藏页自停 |
| 落槌礼花 | **canvas-confetti + `useWorker`** | ~6KB(懒加载) | OffscreenCanvas/Worker 不占主线程；`disableForReducedMotion` |
| 横向系统消息/AI 话语 | 复用现有 `system-barrage`（必要时换 canvas 弹幕引擎） | — | 与纵向瀑布分工 |
| (可选)落槌大礼 | SVGA（设计师产出时） | gz<18KB | 抖音/淘宝直播标准；懒加载 |

### E.2 性能预算（评委必问）
- 帧预算 16.7ms：氛围层**只动 transform/opacity**；canvas 瀑布/礼花离屏或 Worker。
- **治理 10Hz 全树重渲染**（2026-06-05 §4.8 隐患）：100ms 倒计时 tick **下沉到叶子组件** + `React.memo`，氛围组件**事件驱动**而非每 tick 重建。
- 粒子总预算：瀑布≤24 同屏、礼花一次性≤180、低端机/低电量自动减半。
- 懒加载：`canvas-confetti`/SVGA 用 `import()` 在**首次落槌前**才加载，初始包 +0。

### E.3 iOS / WeChat webview 坑（来自 `references`）
- **音频**：`AudioContext` 默认 suspended，须在**首次手势**内 `resume()`（现有 opt-in 提示音按钮正好是这个手势入口）；锁屏/后台 `statechange→interrupted` 要再 `resume()`；iOS 静音键会静音 WebAudio。
- **震动**：`navigator.vibrate` 在 iOS 历史不可靠 → **特性检测、绝不依赖**，纯增强。
- **inline video/alpha-video**：webview 内 alpha 视频可能全屏劫持 → **优先 canvas-confetti/SVGA**，避免 alpha-MP4。

### E.4 文件级改动
- `frontend/mobile-h5/src/`：新增 `BidWaterfall`（canvas 组件）、`PriceOdometer`（CSS 数字条）、`ClimaxLayer`（礼花+聚光+战绩卡）；`atmosphere.ts` 增 `IntensityModel`；`main.tsx` 把瀑布/三态接到 WS 事件 + `cause_seq`；`styles.css` 增升温曲线/扫光/红砸/odometer/战绩卡（均 transform/opacity + reduced-motion 降级块）。
- 音频：扩 `public/audio/auction`（心跳床/落锤/金币/下沉，极小采样或合成）；`playCueTone` 升级为分层 + ducking。

### E.5 验收（扩展 `accept.mjs` + Playwright）
- [ ] 出价后出现瀑布芯片（canvas 存在 + 自我片高亮断言）。
- [ ] 被超越显示真实差额 `被反超 ¥\d+` + 「立即反超」CTA。
- [ ] 末 5s 出现「going once/第一次」且舞台进入 `countdown-phase` 升温态；断连时**不升温**。
- [ ] soft-close 触发时出现「延时 +\d+s」可视化。
- [ ] 落槌出现礼花 + 战绩卡（含**真实**击败人数/成交价）**先于**支付按钮。
- [ ] `prefers-reduced-motion` 下：无瀑布/礼花/脉冲，但计数/差额/战绩卡文本与落槌结果**完整可读**。
- [ ] 全程无伪造数字（禁止项扫描）。

> 收益：用户#2 直觉兑现（瀑布）+ 三态从「通知」变「时刻」+ 末段真·窒息 + 落槌真·高潮——全场最强记忆点，且每一帧都绑真实事件、可降级、不进热路径。
