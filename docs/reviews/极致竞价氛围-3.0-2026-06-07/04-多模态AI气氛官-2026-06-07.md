# 04 · 多模态 AI 气氛官（AI Co-host）

> 用户：「不够多层次（比如加入 AI agent…我已经提供 AI 的 API，文本和多模态都可以尝试）。」

## 2. 设计铁律：AI 是「叙述者」，永不是「裁判」（且这已写进 DDL）

面对「AI 会不会瞎报价格/赢家」的拷打，最强答案是：**约束不是口号，是表结构**。
- `body ≤ 80` 字符 → 物理上不可能长篇胡说。
- `facts_json` → 每条解说**锚定引擎事实**（价格/榜首/延时来自服务端）。
- `safety_json` → 安全标记门控（`repository.go` 的 `result.Safety`）。
- `source_seq`(=`engine_seq`) + `UNIQUE(auction_id,source,source_seq)` → 解说**绑定到具体引擎决策、且幂等去重**，不会对同一事件重复播、不会对未发生的事件解说。
- 出价是否成功/谁赢/价格 → **永远引擎决定**；AI 读权威态、复述，不创造。系统提示 + 输出校验**双保险**禁止 AI 自造数字（呼应 `references` 中 VLM 幻觉风险）。

> 一句答辩：「我们的 AI 连**字数**和**能引用的事实**都被数据库约束死了——它只能把引擎已经决定的真相，说得更好听、更及时。」

## 3. 多视角拷打

- **直播主/达人视角**：补上 2026-06-05 §4.9 指出的「**主播零 hype 杠杆**」最大空洞。中小商家/没口才的主播，也能有「全程高能解说 + 永不冷场」。AI 气氛官接管「又有人扣1了」「榜一要被偷了」「最后 3 秒！」这些**情绪劳动**。
- **商家视角**：`listing_draft` 一张图生成标题/描述/建议起拍价/加价幅度/时长（人审后发布），直击「高价值非标品难定价 + 冷启动」。证据：eBay「Magical Listing」~30% 卖家试用、>95% 采纳 AI 描述（`references`）。
- **用户视角**：永远「有人在说话」的房间 = 不冷场 = 多停留 3 秒。多模态 Q&A（「这翡翠种水怎么样？」配真实拍品图）降低决策门槛。**但视觉判断必须 hedge**（「仅供参考，以第三方鉴定为准」）。
- **PM/创新视角**：数字人主播已是中国直播电商的**生产基建**而非 demo——JD 7 万+ 商家用数字人主播（成本约 1/10）；百度「数字人罗永浩」6 小时 ¥55M、反超真人；硅基智能 50 万克隆数字人。我们不做整张数字人脸（成本/延迟/合规重），做**更轻、更落地、更可控**的「解说气氛官」。
- **后端/SRE 视角**：全程**旁路异步**（worker 队列），AI 挂了**静默回落模板**（已实现），**绝不进出价热路径**、绝不阻塞、绝不报错给买家。与 fail-closed 气质一致。

## 4. 五个能力（映射到已有 job kind，按答辩收益排序）

### 🥇 D-1 实时拍场解说 / 气氛官（`auction_commentary`）——P0，氛围 wow 最高
- **做什么**：在引擎**已决策**的关键事件（新榜首/大幅跳价/末段延时/逼近封顶/going once/落槌）上，流式生成**短促有梗**解说，作为**气氛官存在**呈现（见 §5），激烈度随真实热度（IntensityModel）升温（对标 ICML 2025 Excitement-Driven Commentary、AWS Bundesliga 7–12s、LiveCC token-by-token）。
- **激活**：接 `API_KEY` + `AI_RELAY_MODEL`（硬延迟选 fast tier，如 Haiku 4.5）；事件稀疏（每笔/每延时一条），短输出，**TTFT 150–300ms、e2e <800ms**，成本可忽略；模板兜底已在。
- **真实绑定**：每句带 `source_seq` + `facts_json`，与瀑布/竞速榜同 `cause_seq`。

### 🥇 D-2 多模态鉴品 / Q&A（`product_qa`）——P1，多模态亮点
- **做什么**：房内问「种水/证书/能不能砍价/瑕疵」，基于**拍品结构化数据 + 真实拍品图**（chat_provider 已支持图片）作答；**视觉判断一律 hedge**，不替第三方鉴定背书。
- 证据：阿里现场实验 AI 购物助手 **销量 +3%、退货 -12.55%**（`references`）。命中宣讲版「查看规则/接收提醒」。

### 🥈 D-3 智能加价建议（轻量，可走 commentary/派生）
- **做什么**：从**服务端当前价 + 加价幅度规则**生成 2–3 个加价芯片（「+¥50 守榜一」「+¥100 拉开差距」），用户一键带入出价器。防手滑、降决策成本。
- **铁律**：金额来自**服务端权威价**，不是 AI 编的；只做「建议」，提交仍走引擎校验。

### 🥈 D-4 暖场冷启动（`auction_commentary`，no_bid 触发）
- **做什么**：0 出价时 AI 气氛官开场（拍品看点 + 「等你第一手登顶」），解决空房死亡螺旋。**标注「助手/气氛官」，绝不伪装成真实买家**（反暗黑）。PC 侧已有「冷场提醒」，把它接到买家侧呈现。

### 🥉 D-5 落槌复盘 / 高光（`auction_recap`）——喂给战绩卡
- **做什么**：落槌后由终态 DB 生成「赢家/成交价/出价次数/最大反超」复盘 → **直接喂 `03`§D 的可分享战绩卡** + 商家侧「下一件建议起拍价」。批处理、无延迟压力（WSC 式 1–2 分钟）。

> （`sentinel_explanation` 用于 `05` 防托哨兵的可读解释，不在买家侧。）

## 5. 买家侧呈现：从「飘屏药丸」到「气氛官存在」

现状 AI 的话和系统消息共用一条 6.2s 横向飘屏（`system-barrage`），**无身份、无存在感、无层次**。3.0 给 AI 一个**克制但有存在感**的身份：

```
舞台左上（主播信息下方）：一枚小气氛官身份芯片 + 流式话语带
┌───────────────────────────────┐
│ 🎙 气氛官 · 阿珩   （AI）       │   ← 明确标注 AI（合规）
│ “榜一被偷了！张老板 ¥450 反超， │   ← 流式逐字打出（token streaming）
│  还有 8 秒，李老板要不要拼一手？”│      末段自动升温语气
└───────────────────────────────┘
```

- **三层语言分工**：纵向**瀑布**=出价能量（事件）；横向 `system-barrage`=系统/规则播报；气氛官话语带=**有人格的解说**（流式、可 TTS、可关）。层次感由此而来。
- **TTS 可选、默认关**（复用现有 opt-in 提示音手势解锁 AudioContext）；纯文本即可成立，TTS 是增强。
- **明确「AI」标识**（中国数字人/AI 主播监管要求）；可一键「关闭气氛官」回到纯系统播报。

## 6. 技术与成本（工业级）

- **不进热路径**：commentary 走已有异步 worker（`202606060007`），出价链路零依赖 AI。
- **降级链**：真 LLM 流式 → 超时/失败 → `BuildCommentary` 确定性模板（已实现）→ 最差仅系统模板播报。买家**永远看不到错误**。
- **延迟/成本**：关键事件触发（稀疏）+ 短输出（≤80 字）+ 模板缓存 + fast-tier 模型；TTFT 150–300ms。多模态 Q&A 为**按需单次**调用，非持续。
- **去重幂等**：`UNIQUE(auction_id,source,source_seq)` + worker 去重索引，保证同一引擎事件只解说一次。
- **演示网络兜底**：答辩网络抖动 → 预生成/模板兜底 + 「纯文本解说」降级；演示脚本固定一条「必燃」末段对决解说（`07`）。

**文件级改动**：后端基本复用（接 `API_KEY`、确认 worker 启用、commentary 触发点覆盖 going once/延时/落槌事件）；前端新增 `CohostRibbon`（流式话语带 + AI 标识 + 关闭）、`product_qa` 入口（房内提问，复用半屏）、加价芯片（接 `04`§D-3）；`main.tsx` 把 `auction_system_messages(SYSTEM_AI)` 分流到气氛官带而非通用飘屏。

## 7. 验收
- [ ] 接 `API_KEY` 后，关键事件触发**真 LLM** 流式解说（非模板）；断网时静默回落模板（两条路径都测）。
- [ ] 气氛官带含**明确 AI 标识**、可关闭；TTS opt-in。
- [ ] 解说内容与引擎事实一致（抽查 `facts_json` vs 屏显价格/榜首）；**无 AI 自造价格/赢家**（注入校验）。
- [ ] 多模态 Q&A 对视觉判断**带 hedge 文案**。
- [ ] 0 出价时有暖场解说且标注「助手」，**不伪装真人**。
- [ ] AI 全链路不阻塞出价（关掉 AI 服务，出价/落槌仍正常）。
