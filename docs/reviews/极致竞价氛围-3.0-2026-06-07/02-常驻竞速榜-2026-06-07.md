# 02 · 常驻竞速榜（Always-on Race Board）

> 用户直觉：「把排行榜显示的直接放在外面，固定在那并更新。」——**代码层面完全成立，且是最高 ROI 的一刀。**
> 现状证据：排行榜组件 `LeaderboardPanel`/`LeaderboardRows` 有一流 FLIP 动画（`components.tsx:1162-1258`），但在直播主舞台 `LiveStage`（`components.tsx:25-239`）里**完全不渲染**；只能经「悬浮卡 → 出价半屏 → 出价榜 Tab」**三层交互**才看到（实测 `live-stage` 内 `.leaderboard-row` 节点数 = 0）。直播间静止时**零竞争感**。

---

## 1. 它解决什么（一句话）

把「谁在赢、我第几、差多少」从**埋三层**变成**抬眼即见、实时跳动**——让竞争唤醒（competitive arousal，auction fever 的第一驱动力）在静止帧就开始工作。

---

## 2. 多视角拷打（每条都要能答）

- **用户视角**：刷到直播间的 0.5 秒内，必须立刻 get「这里有人在抢、我能插进去、就差一口」。研究（Ku/Malhotra/Murnighan 竞争唤醒模型，见 `references`）证明：**唤醒只在「相信对手是真人」时触发**——所以常驻榜单（真实脱敏买家 + 实时跳动）是把「围观」转成「下场」的最高杠杆。现状把这个杠杆锁在三层抽屉里。
- **前端视角**：FLIP 已实现且是 transform-only（合成层、60fps 友好）。难点不是动画，是**信息架构**——竖屏视频寸土寸金，不能糊脸。方案：**两态**（静默条 / 事件展开），见 §4。
- **营销/Live-Ops 视角**：榜一/榜二/榜三是中文直播的**社交地位货币**。「守塔/偷塔」叙事（抖音 PK 进度条的灵魂）需要双方位置**持续可见**才能成立。主播一句「榜一要被偷了！」必须有画面支撑。
- **商家视角**：地位感直接驱动加价金额（quasi-endowment：领先越久越「觉得是我的」，丢失越痛）。常驻榜 = 商家的「自动逼单员」，且不需要主播有口才。
- **直播主/达人视角**：榜单是天然解说素材，防冷场。无需高超话术，看着榜单念即可；配合 AI 气氛官（`04`）更省力。
- **后端/SRE 视角**：必须从 REST 重拉改为 **WS 增量推送**，否则常驻榜会放大 10Hz 重渲染隐患——见 §6 性能 + §7 顺手修 outbid 竞态。

## 3. 你比别人强在哪（竞品对比）

| 维度 | 抖音 PK 进度条 | 得物出价榜 | 微拍堂直播 | **本方案 常驻竞速榜** |
|---|---|---|---|---|
| 实时位置可见 | ✅(双方条) | ✅(挂单价) | ⚠️(公屏刷「扣1」) | ✅ 榜一/榜二/榜三 + 我的位置&差距 |
| 反超戏剧 | ✅偷塔/守塔 | ❌ | ✅(主播口播) | ✅ FLIP 名次互换动画 + 「差一口反超」 |
| 数据真实性 | ✅(真打赏) | ✅(真挂单) | ❌**摆拍/虚假参考价**(新华网/新京报查实) | ✅ **引擎权威出价，确定性排序，可对账** |
| 防托/防刷 | 一般 | 一般 | 差(差评见 shill) | ✅ 复用 `auction_risk_alerts` 哨兵(`05`) |
| 排序可解释 | — | 部分 | 否 | ✅ **最高有效金额优先，同额按时间**，规则上屏 |

**一句答辩**：「得物的榜是真的但不热闹；抖音的热闹但和拍卖无关；微拍堂热闹但被查过摆拍。**我们是『热闹 + 真实 + 可对账 + 可解释排序』四者唯一同时具备的。**」

## 4. 交互与线框（IA 纪律：不糊脸）

**两态设计**——静默时极简，有事时展开，事件后自动收回：

```
静默态（rest）— 顶栏下方一条 36px 高的「竞速条」，不挡标题/热度白字：
┌──────────────────────────────────────────────┐
│ 🥇 张** ¥400  ·  我 #2  差 ¥50  ▸           │   ← 一行，tabular nums，点击展开全榜
└──────────────────────────────────────────────┘

事件态（bid_accepted / outbid，~3.2s 后收回）— 展开为 3 行卡，FLIP 名次互换：
┌──────────────────────────────────────────────┐
│ 竞速榜            近30s 12 次 · ¥1,240/分 🔥   │
│ 🥇 张**      ¥450  ↑       3 次               │   ← 金，刚反超者高亮上移
│ 🥈 我        ¥400  ← 你被反超 ¥50  立即反超→  │   ← 「我」行强调 + 真实差额 + 行动召唤
│ 🥉 李**      ¥350          1 次               │
└──────────────────────────────────────────────┘
```

- **位置**：`LiveStage` 顶栏（`video-topbar`）正下方、`stage-safe-zone` 之上，z-index 介于视频与悬浮卡之间。与现有 `system-barrage-layer`（top:86px）错位排布，避免重叠。
- **「我」行永远可见**：即使我在第 8 名，事件态也固定显示「榜一 + …… + 我#8 差¥X」（折叠中间），保证「位置&差距一眼可见」。
- **空态不伪造**：0 出价时显示「等你第一手登顶 🥇」，**绝不填假名**。
- **可访问性**：`aria-live="polite"`，名次变化播报「你升到第 1」；reduced-motion 下取消 FLIP 平移，保留即时重排 + 文本。

## 5. 真实信号绑定（无假数据）

- 榜单 entries = 引擎权威的有效出价聚合（已有 `LeaderboardPayload`：`rank/user_masked/amount_cents/bid_count/is_current/my_rank/gap_to_leader_cents`，`domain.ts`）。
- 热度行 = `accepted_bids_30s` + `price_velocity_cents_per_min`（已有，热度计已在用）。
- 排序规则**上屏可见**（「最高有效出价优先，同额先到先得」），呼应得物的可解释性，且与引擎判定一致——评委问「凭什么这个人榜一」时有据可答。

## 6. 技术规格（工业级落地）

**数据契约（新增 WS 增量，替代 5s REST 重拉）**：
```ts
// WS 推送（房间级），每次引擎接受出价后下发一帧 leaderboard delta
type LeaderboardDelta = {
  auction_id: string;
  cause_seq: number;            // = engine_seq，用于去重/排序，与 cue 共用
  top: Array<{ rank; user_masked; amount_cents; bid_count; is_current }>; // 仅 Top-N(=3~5)
  me?: { rank; amount_cents; gap_to_leader_cents };  // 「我」行，即便不在 Top-N
  heat: { accepted_bids_30s; price_velocity_cents_per_min };
};
```
- 客户端按 `cause_seq` 单调合并；与 `atmosphere` cue 同源 `cause_seq`，**天然修复 outbid 竞态**（§7）。
- **FLIP**：复用现有 `LeaderboardRows` 的 WAAPI FLIP（`components.tsx:1199-1258`，已含 burst 合并）。常驻条只渲染 Top-3 + me，列表短 → FLIP 成本极低。
- **性能（解决 10Hz 隐患）**：竞速条**不订阅 100ms 倒计时 tick**，只在 `LeaderboardDelta` 到达时重渲染（事件驱动，频率=出价速率，远低于 10Hz）。把倒计时 tick 下沉到叶子组件 + `React.memo`，避免常驻榜被全树 reconcile 拖累（呼应 2026-06-05 §4.8 隐患）。
- **突发合并（burst coalescing）**：I=3（沸）时，多笔出价在一个 `requestAnimationFrame` 内合并重排一次（现有 FLIP 已有 `burstMode` 合并逻辑，`components.tsx:1204` 附近），避免抖动。

**组件改动**：
- 新增 `RaceBoard`（`components.tsx`）：两态（rest/expanded）容器，内部复用 `LeaderboardRows`。
- `LiveStage`（`components.tsx:25`）：在 `video-topbar` 后插入 `<RaceBoard .../>`；新增 props `leaderboard`、`leaderboardSeq`。
- `main.tsx`：WS `leaderboard_delta` 事件 → 更新 state；展开/收回用一个 `expandedUntil` 时间戳（事件态 3.2s 后回落）。
- 样式：新增 `.race-board`(rest/expanded)、复用 `.leaderboard-row` 的 FLIP class；新增事件态 `max-height` 过渡（仅 transform/opacity + `content-visibility`）。

## 7. 顺手修：outbid cue 竞态（后端级严谨，前端漏的）

2026-06-05 §4.10-1 指出：「被超越」cue 仅当 `previousLeading`（来自**上次 REST 拉取**的 `my_rank===1`）才触发——两次被超越间若榜单未刷新则**静默丢失**。
**3.0 修法**：被超越改为**事件驱动**——`LeaderboardDelta.me.rank` 由 1→>1（或 `outbid` 引擎事件）直接触发 L3 被超越脉冲，不依赖 REST 新鲜度。WS 增量上线后此 bug 自然消失。

## 8. 验收（可机器判定，扩展 `accept.mjs`）

- [ ] `live-stage` 内可见 `.race-board`，静默态含「🥇 + 金额 + 我#N + 差额」（`accept.mjs` 必需项新增）。
- [ ] 出价后 3s 内竞速条展开为 ≥2 行且「我」行高亮（Playwright 驱动出价后断言）。
- [ ] 被反超后出现真实差额文案 `被反超 ¥\d`（事件驱动，非 REST）。
- [ ] reduced-motion 下无 FLIP 平移但名次正确、文本可读。

- [ ] 竞速条不与 `system-barrage`/标题/热度计重叠（360px 盒模型断言，沿用 06-07 工艺）。
