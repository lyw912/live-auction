## 0. 一页结论（先看这里）

**一句话：你不是“没做”，而是“做了一堆很强的东西，却用 debug 半成品的样子端给了评委”。系统的工程深度在国赛级别属上游；但按它现在默认跑起来的样子，评委大概率会判断它“没做完/看不懂/可能是坏的”，从而看不到你真正的实力。**

三个并存的事实：

1. **能力其实很全且真的能跑。** 真实点击验证：商家发布（含起拍价/加价/封顶/时长/延时/保证金全套规则）、买家出价、领先/被超越、榜单、自动加价、保证金、延时保护、误触确认、落槌成交仪式、输家承接、复盘/高光卡/短视频、出价记录、风控/诊断/事件回放、AI 解说/草稿、liveops（福袋/任务/战队/答疑）——大多**已实现并能端到端跑通**（见 `shots/h5-09-leading.png`、`shots/h5-11-sold.png`）。

2. **它现在“看起来坏了”，根因是数据脏，不是代码坏。** 默认那个直播间里，拍品叫 **`P0 Live Smoke Item`**，价格写着 **“同步中 · ¥350.00 / 本地到零，正在同步”**，出价按钮是灰的 **“同步中”**、并提示 **“权威价格同步中，暂不提交出价”**（`shots/h5-02-sheet.png`）。查库发现：**`auc_live` 这场的 `end_at` 是 7 小时前、`item_title` 为 NULL**；整库累计 **1628 个房间、205 个卡死的 ACTIVE、40 个暂停引擎、12 笔结算失败**（`shots/pc-tab-risk.png`、`shots/pc-tab-diag.png`）。系统**正确地 fail-closed**（这本是优点），但被陈旧数据触发、又用黑话表达，于是“安全降级”被买家读成了“产品坏了”。**重新 seed 一场后，H5 立刻恢复健康：`当前最高价 ¥350.00 · 剩余 09:54 · 竞拍中·已连接 · [出价 ¥400.00]`**（`shots/h5-06-live-clean.png`）。

3. **表达层是 debug 级，不是产品级。** 满屏英文占位名、原始 UUID（`engine_<uuid>`、`ord_<uuid>`）、原始指标（`待同步 50 · 最久 1859758ms`）、哨兵值（`seconds_since_last_bid: 9999`）、商家要按**“分”**输入价格（`起拍价 10000 分`）、原生未美化的 `mm/dd/yyyy` 与 `Choose File`、几十个 `直播间 engine_xxx` 直接铺在界面上（`shots/pc-tab-products-full.png`、`shots/pc-tab-auctions.png`、`shots/pc-01-landing.png`）。

## 2. 核心诊断：三个根因（这是全篇的“题眼”）

> 把所有零散问题归到三条根因，修复才有抓手。

### 根因 A：演示数据脏 → 让“安全降级”看起来像“产品坏了”（P0 demo 阻断）
- 证据：`auc_live.end_at` 早已过期、`item_title=NULL`；全库 1628 房间 / 205 卡死 ACTIVE / 40 暂停引擎 / 12 结算失败。
- 机理：H5 取不到“权威价格快照”，按设计 **fail-closed** 显示“暂不提交出价”。这在架构上**是对的**（符合 `CLAUDE.md` 非协商项：状态不可证明安全时必须 fail closed）。
- 但后果：评委看到的是灰按钮 + “同步中”，**第一印象=没做完/坏了**。
- 已验证修复：`p0smokeseed` 重置一场 → H5 立刻健康可出价（`h5-06`）。**这是录 demo 前的强制前置步骤。**

### 根因 B：表达层是 debug 级（占位名 / 原始 ID / 原始指标 / 单位错误）
- 英文占位：`P0 Live Smoke Item`、`Engine Item`、`P0 live backend smoke item.`
- 原始 ID 上屏：`engine_<uuid>` 当“直播间”名铺几十个、`ord_<uuid>` 当订单号铺一墙。
- 原始指标/哨兵值上屏：`待同步 50 · 最久 1859758ms`、`seconds_since_last_bid: 9999`。
- 单位错误：商家在“竞拍规则”里**按分输入**（`起拍价 10000 分` = ¥100），极易错填。
- 原生控件：`mm/dd/yyyy --:--` 原生日期、`Choose File` 原生上传。
- 行业判定：这正是 B 端“七宗罪”里被各大设计系统明确禁止的（Polaris 人读单号、Ant“动词+名词/单位进表头”、Arco“避免术语/边界情况”）。见《附录》§2.6。

### 根因 C：黑话 + 内部状态机外泄 + IA 堆砌（看不懂 / 不知道怎么用）
- 黑话：`本地到零`、`权威价格同步中`、`已同步最新竞拍状态`（且常重复两遍）、`有效出价 0 人`、`累计 1 口`。
- 状态机外泄：把“恢复中/重同步/权威同步”这些内部态直接写给用户；甚至**领先时仍显示“暂不提交出价”**（`h5-09` 文案 bug，真实原因是“你已领先不能再加价”）。
- IA 堆砌：H5 把信任 chip、弹幕、商品卡全挤在视频左下与一张卡里；**唯一底部 CTA 是“看拍品信息”而非“出价”**，新用户进来不知从何下手。PC 把“真实控制”与“演示驱动（模拟无效出价/第二买家超越/封顶成交）”混在同屏，又把诊断指标灌进每个 Tab 顶栏。

> **一句话题眼：把“安全/可信/可观测”这些工程优点，错误地以“内部日志”的形态暴露给了用户与评委。修复 = 把内部态翻译成人话、把技术 ID/指标收进专门区域、把演示工具与真实操作分区、给一条清晰的主操作路径。**

## 4. 多视角交叉评审（5 位 10 年+ 评委轮流拷打）

> 每位评委只对自己专业域开火，给“最狠的话 + 证据 + 对分数的影响”。

### 4.1 资深前端工程师（字节/TikTok 背景）
- “**进页面我不知道该点哪**。底部唯一按钮是‘看拍品信息’，竞拍产品的第一动作不该是‘出价’吗？”（`h5-01`）
- “**全白卡片、边界不清**，PC 一屏全是同款白卡，信息无层级；H5 左侧 chip 像调试浮层。”（`pc-tab-products-full`、`h5-01`）
- “**内部状态机写给用户**：‘本地到零’‘权威价格同步中’‘已同步最新竞拍状态’还重复两遍——这是把 reducer 日志贴脸上。”（`h5-02`）
- “**原生控件**：`mm/dd/yyyy`、`Choose File` 在 Arco 项目里出现是不可接受的。”
- 影响：**体验维度重扣**；但他也承认“去掉这些，组件骨架其实是齐的”。

### 4.2 产品经理（直播电商）
- “**语义没对齐业务**。‘有效出价 0 人 / 累计 1 口’——商家/买家心智里没有‘口’这种计量；‘第二买家超越’这种**演示工具混进了真实操作区**，评委会怀疑你在‘假装有人’。”（`pc-tab-auctions`）
- “**英文占位 `P0 Live Smoke Item` 直接劝退**，珠宝/收藏品场景却放陶艺图，**品类心智完全错位**。”
- “**没有‘这是什么/我能干什么’的引导**。标杆（Whatnot/抖店）第一屏就回答‘当前价、还剩多久、点这里出价’。”（《附录》§1.1）
- “合规红线：抖音内是**竞拍非拍卖**，要回避‘拍卖’字样且**显著标 7 天无理由**；珠宝直播信任危机极重，**证书要可核验**而不是贴张图。”（《附录》§1.6/1.7）
- 影响：**产品/体验维度重扣**，但功能清单本身能支撑一个很完整的故事。

### 4.3 架构工程师
- “**架构是全篇最强的部分**：Redis 实时决策 + Kafka 决策 WAL/fence + PG 结算真相，fail-closed、对账、故障注入、PTS-1B——这套在参赛项目里属第一梯队。”
- “**但你把它埋了**。评委不会读 `docs/current`。诊断 Tab 一墙 `auc_engine_<uuid>` 既泄漏又无信息增量，**反而像系统在抖动**（`待同步 50 · 最久 1859758ms`、`暂停引擎 40`）。”
- “**数据治理缺位**：1628 房间 / 205 卡死 ACTIVE 是压测垃圾没清，调度/结算被拖累（12 结算失败）。这在生产里是事故，在 demo 里是‘看起来要崩’。”
- 影响：**技术深度本应高分**，但因“不可见 + 脏数据观感”被打折；**给一张架构图 + 一个聚合健康灯就能救回来**。

### 4.4 测试 / SRE
- “**fail-closed 是对的**：`h5-02` 拒绝在不可证明价格时出价、`h5-11` 以结算确认渲染落槌——符合‘不信客户端成功’。这点要表扬。”
- “**但缺少边界文案**：领先时显示‘暂不提交出价’（`h5-09`）是**把两种不同原因（不可提交 vs 已领先无需提交）用了同一句**，会误导。”
- “**演示驱动 `第二买家超越` 实测出价 ¥400 与买家同价**（pass4 日志：‘助手价格来到 ¥400.00’），**没真正反超**——录像里会穿帮。需要让它出‘当前价 + 一口’。”
- “**可观测性指标该有阈值与人话**：`9999` 是没处理的哨兵；`ms` 该格式化为‘约 X 分钟前’。”（《附录》§2.6）
- 影响：正确性观感是加分，但**文案/演示驱动 bug 会在视频里变成减分**。

### 4.5 评委主席（综合 / “我愿不愿意把它评为冠军”）
- “我看到的是一个**工程很扎实、却不会讲自己故事的选手**。三分钟里我没看懂它在干嘛、还以为它坏了。”
- “**它和冠军的差距不在能力，在‘可读性’和‘可信度’**：把英文占位/原始 ID/黑话清掉、给一条‘开拍→出价→被超越→延时→成交→复盘’的干净主线、配 3 分钟讲清楚——它立刻是夺冠候选。”
