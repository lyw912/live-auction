# 前端重构与设计系统（H5 + PC）

> 日期：2026-06-07
> 定位：把“工程师调试台”改造成“评委/用户展示台”的**可落地设计与重构规范**。所有 token、文案、线框都基于真实截图（`shots/`）+ 行业调研（见《附录-行业调研汇编》，本文不重复列 URL）。
> 关联：`审查与评分报告`（问题与优先级）、`Demo编排与录制脚本`（演示）、`附录-行业调研汇编`（来源）。
> 重要边界：本文是**设计与重构方案**，不强制改动现有业务逻辑；落地时优先做“呈现层 + 文案 + 信息架构”，详见 §7 路线与工作量。

---

## 0. 三条设计主线（一切取舍的标尺）

1. **沉浸（C 端）**：直播间是稳定的“家”，视频为底，信息以**半屏/抽屉**渐进披露；主操作（出价）常驻拇指区。
2. **克制（B 端）**：每屏一个核心任务；**一个主按钮**；数据密度优先但有层级；技术指标进专门区域。
3. **可信（全局）**：服务端权威态、等宽数字不跳动、可核验证书、失败即关闭——把“安全/可观测”做成**用户能读懂的信任信号**，而不是内部日志。

> 当前最大病灶就是违反了第 3 条的“可读”：把内部状态机当文案（《审查报告》根因 C）。重构的核心动作是**翻译 + 分区 + 给主路径**。

### 1.3 字体 + 等宽数字（拍卖最重要的一条排版规则）
```css
:root{
  --font-cn:"Alibaba PuHuiTi 3.0",-apple-system,"PingFang SC","Source Han Sans SC","Microsoft YaHei",sans-serif;
  --font-num:"Roboto Mono","SFMono-Regular",ui-monospace,monospace;
}
/* 价格/倒计时/出价数/出价人数：数字不抖动 = 工程可信 */
.price,.countdown,.bid-amount,.stat-num{
  font-variant-numeric:tabular-nums; font-feature-settings:"tnum" 1;
}
```
类型阶（C 端）：当前价/落槌价 **32px·700**；倒计时 **24–28px·700 tabular**；商品名 20·600；正文 16；默认 14；辅助 12。B 端：H1 20·600 / H2 16·600 / 正文 14 / 辅助 12。

### 1.4 动效 + 无障碍
```css
:root{
  --ease-in:cubic-bezier(.05,.7,.1,1);   /* 进入：半屏滑出、价格跳字 */
  --ease-out:cubic-bezier(.3,0,.8,.15);  /* 退出 */
  --ease-std:cubic-bezier(.2,0,0,1);
}
/* 时长：出价确认 150-200ms / 价格跳字 200-250ms / 被超越闪红 进300出200 /
   末10秒倒计时脉冲 1000ms循环1→1.08→1 / 半屏 进300出250 / 落槌仪式 500-600ms */
@media (prefers-reduced-motion:reduce){
  *,*::before,*::after{animation-duration:.01ms!important;animation-iteration-count:1!important;transition-duration:.01ms!important;}
}
```
**铁律**：动效/声效必须**同时有文字+颜色态**（不能只靠动画传达“被超越/成交”）。

### 1.5 声效
默认静音，首次进直播间显式「🔊 开启声音」一键 opt-in，在该 tap 里 `AudioContext.resume()` 并预解码。事件：出价(清脆 0.1–0.3s)/被超越(略低 0.3–0.5s)/末段滴答(0.1s,1/秒)/落槌(木槌+短 fanfare 0.5–1.5s)。素材见《附录》§3.5。

## 2. 文案词典（黑话 → 人话）+ 中文化 + 合规话术

> 这是“看不懂/不知道怎么用”的直接解药。**建议做成全站常量字典 + lint，禁止内部枚举/ID/指标直接上屏。**

### 2.1 必改：黑话→人话（含证据）
| 现状（截图） | 问题 | 改为 |
|---|---|---|
| `本地到零，正在同步` (`h5-02`) | 内部态外泄 | 删除；价格直接显示，或加载时用骨架 |
| `同步中 / 正在同步价格`（常驻、重复两遍）| 看似坏了 | 仅真加载时短暂出现“加载中”；正常态不显示 |
| `权威价格同步中，暂不提交出价`（领先时也显示，`h5-09`）| 两种原因同一句、像 bug | 真不可提交：“正在确认最新价格…”；**领先时**：“你已领先，暂无需加价” |
| `已同步最新竞拍状态`（重复）| 噪音 | 删除 |
| `有效出价 0 人 / 累计 1 口 / 1 口` | “口”非用户心智 | “0 人出价 / 暂无出价”、“1 次出价” |
| `近30秒 0 人` | 像没人/冷清 | 真无人时显示“等待买家进入”；有人显示“X 人在看” |
| `本地 P10 演示资产` | 调试词 | 删除（或后台“演示模式”角标，不进买家视野）|
| `us** / 张**` | 脱敏但无主语 | “买家 张**”/“匿名买家”（榜单/出价流统一口径）|

### 2.2 必改：技术 ID / 指标不上屏（B 端，证据 `pc-*`）
| 现状 | 改为 |
|---|---|
| `直播间 engine_<uuid>`（铺几十个）| 中文房间名（如“翠玉轩·主场”）；技术 ID 进详情抽屉+复制 |
| `ord_<uuid>`（订单一墙）| 人读单号 `JP20260607-0007`；UUID 进详情 |
| `待同步 50 · 最久 1859758ms`（顶栏）| 移到“运行监控”；运营台只留“引擎 ● 正常/降级”健康灯 |
| `seconds_since_last_bid: 9999` | 哨兵值→“暂无出价 / —”；正常显示“X 秒前有出价” |
| `起拍价 10000 分`（按分输入）| 按**元**输入显示 `¥100.00`，内部转分 |

### 2.3 合规话术（抖音内“竞拍≠拍卖”，依据《附录》§1.7）
- **用**：开拍 / 开始竞拍 / 点击出价 / 出一手 / 加一手 / 顶一手 / 中拍 / 竞拍成功 / 落槌成交 / 竞拍结束。
- **不用**：拍卖 / 开始拍卖 / 拍卖出价 / 拍卖成功。
- **必加**：拍品信息处标“**支持 7 天无理由**”；证书提供“**可核验**”入口（机构 + 编号 + 查询深链）。

### 2.4 状态文案矩阵（对齐官方参考图 `official-brief-image-02`）
| 竞拍状态 | 价格文案 | 主按钮 |
|---|---|---|
| 竞拍中·无人出价 | “起拍价 ¥X” | 出一手 ¥起拍价 |
| 竞拍中·已有人出价 | “当前最高价 ¥X” | 出一手 ¥下一口 |
| 即将开拍 | “起拍价 ¥X” | 看详情/提醒我 |
| 你已领先 | “当前最高价 ¥X（你领先）” | 已领先（禁用）|
| 已被超越 | “当前最高价 ¥X” | 反超 ¥下一口（强调）|
| 竞拍结束·未成交（流拍）| “起拍价 ¥X” | 已结束（禁用）|
| 竞拍结束·成交 | “落槌价 ¥X” | 查看结果 |
| 截拍中 | “落槌价 ¥X” | 处理中 |

## 3. H5 重构（用户端）

### 3.1 病灶（截图）→ 目标
- 病：唯一底部 CTA 是“看拍品信息”而非出价（`h5-01`）；左侧 chip 堆砌；视频是陶艺图与珠宝品类错位；黑话满屏。
- 目标：**全屏视频 + 右侧动作栏 + 左下匿名出价流 + 当前拍品 mini 卡 + 拇指区常驻“出价”吸底栏**；其余（信任/榜单/自动加价/规则）收进半屏 Tab。

### 3.2 直播间外壳（线框）
```
┌──────────────────────────────┐
│ ◉翠玉轩·珠宝专场  +关注   👁1.2k  ✕ │  顶部：主播/关注/在看/关闭（细条，半透明）
│                                │
│        [全屏珠宝直播视频/循环]    │
│                            ❤   │  右侧动作栏（拇指可达，居中偏下）
│                            💬   │
│                            ↗   │
│                          🛍商品袋│  ← 抽屉：预展/竞拍中/已结束
│ 匿名买家 出一手 ¥400·当前第2      │  左下：匿名出价滚动流（社会证明，非实名榜）
│ ┌────────────────────────────┐ │
```

### 3.3 出价半屏（线框 + 组件规格）
```
┌──────────────────────────────┐
│            ── 拖拽条 ──      ✕  │
│  距结束 03:12   [⏱延时中 +10s]   │  倒计时 24-28px tabular，末段变 #FE2C55 脉冲
│  翡翠A货平安扣   🏅证书可查        │
│  当前最高 ¥350(张**领先)  我的出价 —│  价格 32px tabular
│  ┌── 你已领先 / 已被超越 ─────┐  │  状态 banner（成功绿/告警红）
│      −      ¥400      +          │  stepper：默认下一口；加价幅度 ¥50
│  ┌────────────────────────┐    │
│  │      ← 滑动出一手 ¥400      │    │  主 CTA #FE2C55，滑动/长按确认
│  └────────────────────────┘    │
│ [拍品与规则] [出价榜] [自动加价] │  Tab 折叠其余（去黑话）
└──────────────────────────────┘
```
- **CTA 文案随状态**（见 §2.4）：领先→“已领先（禁用）”；被超越→“反超 ¥X”；不可提交→“正在确认价格…”。
- **拍品与规则 Tab**：把现有信任详情（证书/品相/尺寸/材质/瑕疵/运费/保证金/延时/误触/售后，`h5-03`）保留，**但分组卡片化 + 去“待同步”占位 + 证书加“可核验”链接**。
- **出价榜 Tab**：匿名 + 自己的私有名次（“您当前第 1/第 3”），非实名公开榜（依据《附录》§1.5）。

### 3.4 结果仪式（赢家/输家，对齐 `h5-11` + 官方 `image-06`）
- 赢家：全屏“落槌！恭喜竞得 ¥X”+ 金色点缀 + 限时支付卡（含运费、保证金抵扣说明）。
- 输家：克制“本场惜败 · ¥X 成交 · 你差 ¥200”+ “下一件/关注开播/同款求购”。
- 流拍：“无人出价 · 未达起拍”+ 再拍一次。
- **全部以服务端结算渲染**，不以客户端倒计时归零为准。

## 4. PC 重构（商家/主播端）

### 4.1 病灶 → 目标
- 病：诊断指标灌进每个 Tab 顶栏；真实控制与“演示驱动”混排；全白卡片无层级；价格按分；原生控件；订单/房间一墙 UUID（`pc-*`）。
- 目标：**三工作区分离 + 单主按钮控场 + 四组发布表单 + 状态机标签 + 人读订单表 + 聚合健康灯 + 独立运行监控**。

### 4.2 导航三工作区（把“数据/操作/记录”分开，行业范式）
```
顶栏： 直播竞拍台          [主直播间 ▾]    引擎 ● 正常      🔔  我
侧栏： ① 开播中控   ② 拍品与规则   ③ 订单记录   ④ 运行监控(诊断)
                                         └ 原始指标/事件回放/对账全部进这里
```
> 关键：把 `待同步/最久 ms/暂停引擎/9999` 等**全部移入④**；①②③只出现“引擎 ● 正常/降级/异常”一个聚合灯，点击进④。

### 4.3 ① 开播中控（三栏驾驶舱 + 单主按钮）
```
┌── 队列(可调序) ──┬──── 当前拍品/场面 ────┬──── 控制 + 互动 ────┐
│ ①翡翠平安扣 进行中 │  [大图]               │ [ 开始竞拍 ]  ←唯一主按钮(蓝)│
│   当前 ¥350 ·3次   │  翡翠A货平安扣          │ 讲解 上一件 下一件  ←次按钮 │
│ ②和田玉牌 待开拍   │  当前最高  ¥350        │ 结束本场  ←危险(红,二次确认)│
│ ③蜜蜡手串 草稿     │  距结束   03:12        │ ───────────────── │
│                   │  出价 3次·在看 1.2k    │ ▸ 演示助手(抽屉)          │
│                   │  状态 [进行中]green     │   模拟另一买家/末段延时/封顶 │
│                   │                        │   标注“录屏加速·走真实后端”│
└───────────────────┴───────────────────────┴───────────────────────┘
```
- 按钮分层依据 Ant：一区一个主按钮，次要收溢出，危险红 + 二次确认 + 后果文案（“结束本场后不可恢复”）。
- **演示驱动**（模拟无效出价/第二买家超越/窗口延时/封顶成交）**收进“演示助手”抽屉**，与真实控制分区并加标签。

### 4.4 ② 拍品与规则：四组发布表单（单列、失焦校验、按元、智能默认）
```
拍品信息   标题* | 主图(上传,限5M/JPG·提示3:4) | 类目 | 描述
竞价规则   起拍价 ¥[100.00] | 加价幅度 ¥[50.00] | 封顶价 ¥[600.00] | 0元起拍▢
           保证金 比例[10%] 下限¥[50] 上限¥[500]
场次与时间 开拍时间(24h) | 时长[10分钟▾] | 末段延时窗口[10秒▾] 每次延时[10秒] 最多[3]次
履约       发货时效 | 运费 | 退换：支持7天无理由▢
[ 保存草稿 ]            [ 发布并排期 ]   ← 主按钮
```
- **按元输入**（内部转分），校验“加价>0/封顶≥起拍”，**失焦校验**不逐键打断。
- 延时/封顶旁给人话说明（“最后 10 秒有人出价则自动延长 10 秒，最多 3 次，防最后一秒抢拍”）。
- 原生 `mm/dd/yyyy`、`Choose File` 换 Arco DatePicker/Upload。

### 4.5 ③ 订单记录（人读单号 + 脱敏 + 金额右对齐千分位）
```
单号               买家     金额(元)     状态      成交时间          操作
JP20260607-0007    张**    ¥6,000.00   待支付    06-07 10:21      详情  ⋯
JP20260607-0006    李**    ¥3,200.00   已支付    06-07 10:05      详情  ⋯
```
- 文本左/数值右/表头不居中；金额千分位、全表两位小数；空值 `-`；技术 ID 进“详情”抽屉+复制；行操作多于 2 个收“更多”；>50 条分页；筛选项带计数（草稿 3 / 进行中 1 / 已成交 12）。

### 4.6 状态机标签（Arco Tag 预设色）
草稿 gray · 待开拍 arcoblue(#165DFF) · 进行中 green · 延时中 orange · 已成交 green · 流拍 gray · 已取消 red。**绝不显示 `STATE_LIVE/terminal` 等枚举名**。

### 4.7 ④ 运行监控（诊断，独立区，可读化）
- 指标卡优先（最关键放左上）：引擎健康、结算积压、出价确认延迟、暂停引擎数；裸 ms→“约 X 分钟前”，`9999`→“暂无出价”。
- 事件回放/出价记录/对账放这里——既是工程深度展示位，也是 demo 防“作假”的证据位。
- **演示库治理入口**（可选）：一键清理压测残留房间（当前 1628 房间/40 暂停引擎是噪音，见《审查报告》§2-A）。

## 7. 落地路线与工作量（不重写系统）

> 现状代码是**单文件巨石**：H5 `main.tsx`(1931 行)+`components.tsx`(1743)+`styles.css`(2818)；PC 同构。这放大了“混乱堆砌”观感，但**重构不必一次拆完**——按下面顺序做“呈现层手术”，每步都能单独验收。

**阶段一（Demo 前必做，多为 S/M）**
1. 数据治理 + 中文种子（《Demo》§1）—— S
2. 文案词典落地（§2.1/2.2）：把黑话/ID/指标替换或下沉 —— M
3. H5 给吸底出价主路径 + 领先态文案 bug 修复 —— M
4. PC 顶栏剥离指标 + 价格按元 + 演示助手分区 —— M

**阶段二（上分，M）**
5. 固化 §1 token：暗色 C 端 + 金/香槟价值色 + tabular-nums —— M
6. PC 三工作区拆分 + 四组发布表单 + 人读订单表 + 状态标签 —— M–L
7. 原生控件换 Arco；空/错/加载三态 —— M

**阶段三（可选打磨，L）**
8. 巨石拆分：H5 按“直播外壳/出价半屏/拍品半屏/榜单/结果/状态机”拆组件与样式；PC 按工作区拆。
9. 珠宝循环视频、声效 opt-in、动效曲线、reduced-motion。

**验收 Checklist（逐条勾）**
- [ ] 全站无英文占位名 / 无原始 UUID / 无原始 ms / 无哨兵 9999 / 无“分”输入。

- [ ] 领先/被超越/成交各有独立文案 + 颜色，且与服务端态一致。
- [ ] 价格/倒计时使用 tabular-nums，不抖动。
- [ ] PC ①②③屏无诊断指标；仅一个健康灯；④集中监控/回放/对账。
