## 1. 交战规则 / 不可逾越的护栏（Rules of Engagement）

> 违反任何一条都判定“跑偏”，需回退。

- **R1 不碰服务端权威与正确性逻辑。** 不得改：出价是否成功的判定、价格/赢家/倒计时/终态的来源、fail-closed/恢复/对账、幂等、`/api/*` 契约。你改的是**呈现层（文案、布局、组件、样式、信息架构）**。后端 `backend/**` 除 `cmd/p0smokeseed`（仅演示种子）外**不改**。
- **R2 不加新功能。** 不得新增福袋/PK/答疑等模块或新业务能力。只重组、改文案、改样式、补三态（空/错/加载）。需求范围 = 本手册工单集合。
- **R3 文案/数值只用唯一真相源（§3）。** 不得即兴造词。新增用户可见文案必须进 `copy` 常量并符合“无黑话/无英文占位/无原始 ID/无原始指标/合规话术”。
- **R4 保留 fail-closed 语义，只改它的“说法”。** 例：价格不可证明时仍禁用出价，但文案从“权威价格同步中，暂不提交出价”改成人话“正在确认最新价格…”。**不要为了让按钮可点而绕过安全判定。**
- **R5 每个工单自带验证，红了不算完。** 见 §2、§5。不允许“看起来改了”就标完成。
- **R6 最小 diff、可回退。** 一个工单一组提交，提交信息写清工单号与命中门禁。不顺手重构无关代码。
- **R7 不镀金、不扩散。** 不超出工单范围“顺便优化”。不确定时按 §6 协议停下确认，而不是猜。
- **R8 不破坏移动端。** H5 改动需在移动视口（375–414px 宽）自测无溢出、无遮挡安全区、主操作在拇指区。

### 2.2 生产级验收（强烈建议落地，覆盖更全）
把快速脚本升级为 `@playwright/test` 套件（来源见《附录》§验收调研）。最少四类用例：
1. **web-first 断言 + 自动等待**（不要 `waitForTimeout`）：

5. **确定性**：`page.clock.setFixedTime(...)` 冻结倒计时；每次先 seed；`animations:'disabled'`。

### WO-2 · H5 领先态文案 bug（核心正确性观感）

  - 本人领先：`你已领先，暂无需加价`（按钮禁用，文案为信息而非告警）
  - 真不可提交（价格未确认）：`正在确认最新价格…`（保留 fail-closed，仅改说法，遵 R4）
- DoD：领先态**不再出现** `暂不提交出价`；出现 `你已领先`。
- 验证（权威）：代码复核 + 生产用例 §2.2(1)：
  ```ts
  // 进入领先态后
  await expect(page.getByText(/你已领先/)).toBeVisible();

  ```
  （`accept.mjs` 两项作辅助。）

### WO-7 · PC 房间名不露 UUID + 过滤压测房间
- 现状：`components.tsx:34-37 roomDisplayName` 对未知房间 `return roomID.replace(/^room[_-]?/i,'直播间 ')` → 把 `room_engine_<uuid>` 显示成 `直播间 engine_<uuid>`；房间下拉灌满压测房间。
- 改法：
  - `roomDisplayName`：未知房间显示中性名（如 `直播间`，或基于序号/host 的人话名），**绝不拼接原始 ID**；技术 ID 仅在“详情/复制”出现。

- DoD：`accept.mjs` “原始UUID(chrome)”“engine_ID” ✅。
- 注意：过滤是**展示层**过滤，不删后端数据（R1）。

```tsx
export const centsToYuan = (c?: number|null) => c==null ? undefined : c/100;
export const yuanToCents = (y?: number|string|null) =>
  y==null||y==='' ? null : Math.round(Number(y)*100); // Math.round 防浮点
<InputNumber prefix="¥" min={0} precision={2} step={1}
  value={centsToYuan(valueCents)}
```
