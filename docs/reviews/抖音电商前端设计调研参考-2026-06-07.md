我将进行广泛调研，收集工业界短视频电商 feed 流与商家后台的真实设计实践、规范与资源。
基于对抖音、TikTok、快手、淘宝直播、Ant Design、TDesign、Shopify 等工业界真实产品的广泛调研，以下是针对**短视频电商 Feed 流（C端）**与**商家后台（B端）**的完整前端设计指导方案。本方案可直接用于项目评审、设计走查与前端代码审查。

---

## 一、指导思想与核心原则

### 1.1 C端 Feed 流 / 直播页：沉浸式消费设计
- **拇指法则**：所有核心操作（点赞、评论、分享、购买）必须落在单手拇指热区内（屏幕下半部 1/3 区域）。底部交互区高度建议 ≥ 120px。
- **零 friction 购买**：从“看到商品”到“点击购买”的链路不得超过 2 次点击，且不能打断视频播放。
- **信息密度克制**：单屏视频区域占比 ≥ 70%，文字信息层采用悬浮/半透明底方式叠加，避免遮挡主体内容。
- **实时反馈优先**：点赞、关注、送礼等操作必须在 100ms 内给出本地 UI 反馈，网络请求后补正。

### 1.2 B端商家后台：效率与密度设计
- **任务导向**：每个页面围绕单一核心任务展开，采用“侧边导航 + 面包屑 + 页面标题”的三级定位体系。
- **数据密度 > 视觉表现**：表格、表单、图表占据主要空间，留白控制在 8–16px 级别，而非 C端的 24–40px。
- **一致性压倒创新**：严格遵循设计系统（Ant Design / TDesign / ArcoDesign），同一类操作在不同模块中的按钮位置、文案、颜色必须完全一致。
- **防错与撤销**：批量操作、删除、改价等高风险动作必须二次确认，并提供操作日志与回收站。

## 二、陷阱与盲区（工业界血泪教训）

### 2.1 C端 Feed 流常见陷阱
| 陷阱 | 后果 | 正确做法 |
|------|------|----------|
| **DOM 爆炸式无限滚动** | 滚动 50 条后页面卡顿、内存泄漏、低端机崩溃 | 必须采用虚拟列表（Virtual List）或 DOM 回收机制，仅保留视口上下 3 屏内的 DOM 节点。 |
| **视频自动播放无节制** | 流量偷跑、电池耗尽、多视频同时播放导致解码器崩溃 | 视口内最多同时播放 1 个视频，其余暂停并释放 `video` 标签资源；非 Wi-Fi 环境下默认静音播放。 |
| **图片/封面无懒加载** | 首屏加载 > 5s，3G 网络直接流失 | 所有封面图使用 `IntersectionObserver` 懒加载，占位图采用 LQIP（低质量预览图）或骨架屏。 |
| **骨架屏与真实布局错位** | 内容闪现（CLS）导致用户误点击 | 骨架屏必须与真实组件的宽高、圆角、间距像素级一致，使用 CSS 动画而非 GIF。 |
| **忽略安全区与刘海屏** | 按钮被 iPhone 灵动岛或底部横条遮挡 | 使用 `env(safe-area-inset-*)` 适配，核心按钮避开屏幕四角 34px 安全区。 |

### 2.2 B端商家后台常见陷阱
| 陷阱 | 后果 | 正确做法 |
|------|------|----------|
| **表格横向滚动条** | 用户无法一屏看完关键数据，体验极差 | 首屏必须展示所有核心字段；超宽字段使用 Tooltip 截断，而非横向滚动。 |
| **表单字段类型全用文本** | 日期不能筛选、金额不能计算、状态不能色块化 | 严格按数据类型选择组件：日期→DatePicker、状态→Tag/Select、金额→带千分位的 InputNumber。 |
| **事件监听死循环** | 表单联动时浏览器卡死 | 使用 `isInternalChange` 标志位区分用户触发与代码触发，避免互斥逻辑循环调用。 |
| **按钮文案模糊** | 用户不敢点击“确定” | 按钮文案必须是动词+名词，如“发布商品”“确认退款”，禁用“确定”“提交”。 |
| **无空状态与加载态** | 新用户面对空白页面不知所措 | 每个列表、图表、详情页必须有 Skeleton、Empty、Error 三种状态设计。 |

## 三、排版风格规范

### 3.1 字体与字号体系
**C端（Feed 流 / 直播）**：
- 字体栈：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', sans-serif`（系统字体优先，保证渲染速度）。
- 字号层级：
  - 视频标题/昵称：16px–18px，Bold，行高 1.4
  - 商品标签/价格：14px，Bold，价格使用 DIN / Roboto 等宽字体增强数字跳动感知
  - 辅助信息（点赞数、评论）：12px，Regular，行高 1.3
  - 直播间弹幕：14px，白色带 1px 黑色描边，确保在任何视频背景上可读

**B端（商家后台）**：
- 字体栈：`"Inter", "SF Pro Display", -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`
- 字号层级：
  - 页面标题（H1）：20px–24px，Medium
  - 模块标题（H2）：16px，Medium
  - 正文/表格：14px，Regular，行高 1.5（Ant Design 标准）
  - 辅助/注释：12px，Regular，行高 1.5
  - 最小字号：12px（低于此值在 1440px 屏上无法清晰阅读）。

### 3.2 间距与栅格
- **C端**：采用 4dp 基线网格。卡片内边距 12px–16px，元素间距 8px/12px/16px 三档。屏幕左右留白 12px（移动端）。
- **B端**：采用 8dp 基线网格 + 24 栅格体系。页面内容区宽度 1200px–1440px 居中，侧边栏 200px（可折叠）。
- **圆角规范**：
  - C端视频卡片：0px（全屏沉浸）或 12px（双列瀑布流）
  - C端商品浮层：16px 大圆角，柔和弹出感
  - B端数据卡片：4px–8px 小圆角，专业克制
  - 同一界面圆角类型不超过 2 种。

## 四、色彩运用规范

### 4.1 C端：高饱和情绪驱动
- **主色（品牌色）**：电商红/橙（如 `#FF5000` 淘宝橙、`#FE2C55` TikTok 红），仅用于“购买”“立即抢”等最强 CTA。
- **功能色**：
  - 成功： `#00B578`（关注成功、支付成功）
  - 警告： `#FF7D00`（库存紧张、即将售罄）
  - 错误： `#FF4D4F`（抢购失败、网络断开）
- **中性色**：
  - 文字主色：`#FFFFFF`（视频上层）、`#1D2129`（白色背景页）
  - 文字次色：`#FFFFFF` @ 60% 透明度（视频上层）、`#4E5969`（白色背景页）
  - 分割线与遮罩：`#000000` @ 40% 透明度（视频上层渐变蒙版）
- **暗色模式**：直播/视频页默认暗色背景，减少 OLED 烧屏并突出内容。

### 4.2 B端：低饱和效率驱动
- **背景层级**：Page（`#F2F3F5`）→ Surface（`#FFFFFF`）→ Overlay（`#FFFFFF` with shadow）。
- **文字层级**：Primary（`#1D2129`）→ Secondary（`#4E5969`）→ Tertiary（`#86909C`）→ Disabled（`#C9CDD4`）。
- **数据可视化色板**：保持色相区分度，避免红绿色盲无法辨识；图表最多使用 8 个主色，超出的用透明度区分。
- **对比度**：所有文字与背景对比度必须 ≥ 4.5:1（WCAG AA 标准），关键操作按钮 ≥ 7:1（AAA）。

## 五、动效与声效设计

### 5.1 动效原则
- **有目的的动效**：每个动画必须服务于“理解”或“愉悦”，禁止无意义的装饰性动画。
- **时长规范**：
  - 微交互（点赞、开关）：150ms–200ms
  - 页面转场：250ms–300ms
  - 模态框/浮层弹出：200ms–250ms
  - 全屏礼物特效：3s–15s（可配置跳过）
- **缓动曲线**：
  - 进入：`cubic-bezier(0.32, 0.94, 0.60, 1)`（快速启动，柔和停止）
  - 退出：`cubic-bezier(0.32, 0.08, 0.24, 1)`（迅速消失，不拖沓）
  - 强调（点赞心跳）：`cubic-bezier(0.68, -0.55, 0.27, 1.55)`（弹性回弹）

### 5.2 C端关键动效
- **点赞双击**：双击屏幕出现红心飘升动画，心形路径随机 ±15° 偏移，透明度 0→1→0，持续 800ms。
- **礼物特效**：采用 SVGA / VAP 格式播放全屏动画，支持粒子系统（如飘落花瓣、发光轨迹），时长 3–15s，可点击“屏蔽特效”立即终止。
- **商品浮层滑出**：从底部以 `translateY(100%) → translateY(0)` 滑出，带遮罩层 `opacity 0→0.6`，点击遮罩或下滑关闭。
- **直播弹幕**：从右向左匀速滚动（`linear`），速度根据字数动态计算（约 100px/s），避免遮挡主播面部（弹幕区域限制在屏幕上半部 1/3 以下）。

### 5.3 声效设计
- **原则**：默认关闭，用户首次进入直播间时明确提示“是否开启声音”；所有声效必须支持单独关闭。
- **音源类型**：
  - 礼物声效：清脆短促（如金币掉落、风铃），时长 < 1s，音量 0.3–0.5
  - 消息提示：柔和不刺耳（如水滴声），避免与系统通知声冲突
  - 直播背景音乐：由主播端控制，观众端可独立调节音量或静音
- **技术实现**：使用 Web Audio API 预加载音源，避免 HTML5 Audio 的延迟；短音效采用 Base64 内联 Data URI 减少请求。

## 六、组件设计规范

### 6.1 原子设计方法论
采用 Atomic Design 构建组件库：原子（颜色、字体、图标）→ 分子（按钮、输入框）→ 组织（商品卡片、评论项）→ 模板（Feed 页、直播间）→ 页面。

### 6.2 C端核心组件
**视频卡片（Video Card）**：
- 宽高比：9:16（全屏）或 3:4（瀑布流）
- 封面图：带 3px 圆角，加载中显示灰色骨架屏（宽高比与视频一致）
- 信息层：底部 120px 渐变蒙版（`linear-gradient(to top, rgba(0,0,0,0.6), transparent)`），昵称、标题、音乐信息左对齐，点赞/评论/分享右对齐垂直排列。
- 交互：长按 500ms 弹出“不感兴趣/举报”菜单；单击暂停/播放。

**商品浮层（Product Sheet）**：
- 高度：屏幕 70%–85%，顶部 8px 拖拽指示条
- 内容：商品轮播图（圆角 12px）+ 标题 + 价格（大字号，红色）+ 规格选择器 + 立即购买按钮（吸底，高度 48px，全圆角）
- 动效：上滑进入，下滑退出（阻尼感）。

**直播间弹幕（Barrage）**：
- 背景：用户昵称带品牌色，消息内容白色，整体背景 `rgba(0,0,0,0.2)` 圆角 4px
- 优先级：系统消息（黄色背景）> 用户等级（高等级带边框）> 普通消息

### 6.3 B端核心组件
**数据表格（Data Table）**：
- 行高：48px（单行的舒适点击高度）
- 列宽：根据内容类型设定固定宽度（如日期 120px、金额 140px、状态 100px），避免列宽拖拽导致的布局混乱。
- 操作列：固定右列（`position: sticky`），最多展示 2 个图标按钮，更多操作收入 Dropdown。
- 批量操作：表格左上角复选框全选，顶部出现批量操作浮层（`position: fixed`），包含“批量上架/下架/删除”。

**表单（Form）**：
- 标签对齐：右对齐（减少眼球移动距离）或顶对齐（移动端/复杂表单），禁止左对齐。
- 输入框宽度：用宽度暗示内容长度（如手机号 160px，商品标题 100%）。
- 校验时机：失焦（Blur）时校验，而非输入时实时打断（除密码强度外）。
- 必填标识：用“*”标记必填项，但优先通过默认值、智能推断减少必填项数量。

**图表（Chart）**：
- 实时数据（如直播 GMV 曲线）：使用 ECharts / AntV G2，带平滑曲线（`smooth: true`），数据更新时采用差异动画（300ms 过渡）。
- 核心指标卡片（KPI Card）：大字号数字 + 环比箭头（绿色上升 ▲ / 红色下降 ▼）+ 迷你折线图（Sparkline）。

## 七、页面构成要素

### 7.1 C端 Feed 流页面结构
```
[Status Bar] 系统状态栏（时间、电量）
[Video Layer] 全屏视频层（占 100% 视口）
  ├─ Top Mask: 顶部渐变遮罩（返回、搜索、相机入口）
  ├─ Right Actions: 右侧垂直操作栏（头像+关注、点赞、评论、分享、音乐唱片）
  ├─ Bottom Info: 底部信息区（昵称、标题、音乐、商品锚点）
  └─ Bottom CTA: 底部商品橱窗入口 / 直播间入口
[Overlay] 浮层系统（评论弹窗、商品详情、分享面板、礼物面板）
[Toast] 轻提示（网络状态、关注成功、复制链接）
```

### 7.2 B端商家后台页面结构
```
[Global Header] 全局顶栏（Logo、搜索、消息、账号、语言切换）
[Sidebar] 侧边导航（一级图标 + 文字，可折叠；二级菜单展开）
  ├─ 核心模块：商品、订单、营销、数据、财务、设置
[Breadcrumb + Title] 面包屑 + 页面标题 + 全局操作（如“发布商品”）
[Content Area] 内容区（24 栅格自适应）
  ├─ Filter Bar: 筛选栏（日期、状态、关键词、高级筛选）
  ├─ Action Bar: 操作栏（批量操作、导出、自定义列）
  ├─ Data Table/Form/Chart: 主内容区
  └─ Pagination: 分页（页码 + 每页条数 + 快速跳转）
[Footer] 页脚（版权信息、客服入口，通常极简）
```

## 九、前端审查 Checklist（可直接用于 Code Review）

### C端 Feed 流 / 直播
- [ ] 视频播放是否使用 `IntersectionObserver` 控制单实例播放？
- [ ] 图片是否全部使用懒加载 + 占位图/骨架屏？首屏请求数 ≤ 6 个。
- [ ] 点赞、关注等操作是否有 100ms 内的本地乐观更新？
- [ ] 是否处理了 iOS 底部安全区与 Android 异形屏适配？
- [ ] 礼物特效是否支持“屏蔽”与“性能降级”（低端机禁用粒子）？
- [ ] 是否做了弱网/无网状态下的空状态与重试机制？

### B端商家后台
- [ ] 是否基于 Ant Design / TDesign 等成熟组件库，而非从零自研？
- [ ] 表格列宽是否固定，避免出现横向滚动条？
- [ ] 表单校验是否在 Blur 时触发，而非输入时打断？
- [ ] 批量操作是否有二次确认与操作日志？
- [ ] 是否使用 8dp 间距体系与 24 栅格布局？
- [ ] 所有按钮文案是否为“动词+名词”，禁用“确定”？
- [ ] 是否包含 Skeleton、Empty、Error 三种状态组件？
